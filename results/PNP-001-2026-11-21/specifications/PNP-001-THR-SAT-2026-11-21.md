# PNP-001 direction 1 - algorithmic method on THR o THR (owner approved 2026-11-21: "Ja ... Forsche bitte selbstständig weiter")

## Why this direction
A faster circuit-analysis algorithm is itself the progress the owner counts ("a faster algorithm with proved running time"), and a proved
bridge turns it into a lower bound:
- PROVED TRANSFER (source-checked, spec PNP-001-LIT-7-2026-11-21.md): Chen-Tal-Wang ECCC TR26-039 Lemma 3.8 (from Bathie-Williams ITCS 2024
  Thm 3.7 + Chen-Williams 2019 Lemma 25): for every alpha > 1, a 2^n / n^{omega(1)}-time CAPP algorithm (additive error o(1)) for
  O(n^alpha)-size XOR_2 o THR o THR circuits implies E^NP has no n^alpha-size THR o THR circuits.
- State of the art (same source): E^NP not in THR o THR of size n^{2.5-o(1)}.
- Consequence on success: new E^NP lower bounds at the TC0 frontier - NOT P != NP by itself.
Further literature (from memory, VERIFY the exact statement before citing it in a claim): Williams 2011/2014 (ACC0-SAT => NEXP not in ACC0);
Impagliazzo-Paturi-Schneider FOCS 2013 (SAT for sparse depth-2 threshold circuits); Chen-Santhanam-Srinivasan CCC 2016 (#SAT and
average-case bounds for threshold circuits with few wires); Kane-Williams STOC 2016 (depth-2/3 threshold circuit lower bounds).

## The automatic evaluator (new, 2026-11-21)
- thr_algo_evaluate {code}: code defines count_sat(n, W, t, v, T) -> exact #SAT of f(x) = [sum_j v_j [W_j . x >= t_j] >= T],
  m = ceil(n^alpha) bottom gates (default alpha = 1.5). The sandbox checks exactness against brute force on four families (random,
  majorities, sparse_sat, large_weights) and reports growth_exponent = slope of log2(time / (m n)) over n. Brute force = 1.0
  (baseline cm-963a622f081f4c6c: 1.022).
- thr_frontier: the best correct entries with code. Every evaluation is archived and is a host-observed lab experiment (citable id).
- An empirical exponent on n <= 20 is a LEAD. It is progress only after a proof of the running time (2^n / n^{omega(1)}, or
  2^{(1-delta) n}) for the whole class at the stated size.

## Proof obligations (what counts, per the owner's progress rule)
O1 An algorithm + PROOF: #SAT (or CAPP with additive error o(1)) for THR o THR of size n^alpha in time 2^n / n^{omega(1)}, alpha as large as
   possible; beyond alpha = 2.5 it is new; XOR_2 o THR o THR is the class Lemma 3.8 needs.
O2 Intermediate theorems with proofs: savings for restricted subclasses (polynomial weights, bounded fan-in of the top gate, few distinct
   bottom gates, read-k inputs) - each a proved running time, kind ALGORITHM, closes O1 for that subclass.
O3 Structural lemmas the algorithms rest on: e.g. a restriction / decomposition lemma that simplifies THR o THR under random restrictions
   with a proved success probability; polynomial or rational representations of THR gates usable by the polynomial method.

## Method (generate -> evaluate -> mine -> prove)
1. GENERATE many candidate algorithms (branching orders, memoised partial sums, meet-in-the-middle on bottom-gate sums, restriction-based
   simplification, polynomial-method style evaluation, learned branching heuristics) - mutate and combine frontier entries.
2. EVALUATE with thr2_evaluate (v2: same-instance baseline, held-out and adversarial instances; objectives sharp_sat and capp_xor).
3. MINE: why is the best one faster? Measure what it prunes (e.g. how many bottom gates become constant after k fixed variables), fit
   the dependence, find the invariant.
4. PROVE the running time from the mined mechanism; record the proof as proof_state_update kind ALGORITHM closes O1/O2.

## Where the exponent 2.5 comes from (director, source-checked in local eccc-TR26-039/paper.txt, sections 2.1 and 5, 2026-11-21)
- 2 = the ACW16 / Tam16 step: a SYM gate on m' inputs has a probabilistic F2 polynomial of degree ~sqrt(m'); Williams' batch evaluation needs
  degree < n^{1-eps/3}, so at most ~n^{2-eps} (sub-quadratic) bottom gates may stay alive.
- + 1/2 = the KW16 random restriction: with n^delta variables alive, a THR gate stays non-constant with probability about n^{delta}/sqrt(n);
  so m = n^{2.5-eps} gates leave about n^{2-eps/2} survivors (paper.txt line ~692).
- The 1/2 is tight for majority-like gates (anticoncentration), so beating 2.5 needs ONE of:
  (a) an analysis step for SYM o THR with SUPER-quadratically many alive gates - i.e. beat the quadratic barrier on the restricted circuit,
      using that the survivors are structured (they depend only on the n^delta alive variables);
  (b) a better survival bound for a SUBCLASS (large / sparse / structured weights) - an intermediate theorem, lane B/C;
  (c) replace the sqrt(m') degree step for a subclass: e.g. LOW-RANK survivors (lane D, Q-9d5ab93ad8: if the restricted weight matrix has
      rank r, all gates are functions of r linear forms and the number of gates stops mattering). Novelty not checked.
- Lane obligations: (a) is the real target; (b) and (c) are intermediate goals in the sense of the owner rule "Zwischenziele zuerst".
