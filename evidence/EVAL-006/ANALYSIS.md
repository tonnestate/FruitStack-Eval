# EVAL-006 result (exploratory, n = 20): full FruitStack organization vs one model call on BigCodeBench-Hard

Pre-registration: `PREREG.md` (commit ebe03b7, before any model call). Run 2026-11-12 as pre-registered: interleaved per task (SINGLE then ORG),
zero cash (cost_usd 0 on every receipt), no re-attempt was needed (every task-arm received model output and produced a candidate), no host crash.
Grading: blind (opaque keys, shuffled, ids and code only), official in-process semantics in bwrap + tamper audit, pinned grader venv; 68 candidates graded
(20 SINGLE, 20 ORG, 28 ORG final positions). Tables generated by `runners/eval006.py analyze`: `ANALYSIS_TABLES.md`; rows: `graded.jsonl`, `results.jsonl`,
`accounting.json`; raw files (task texts, answers, stderr) stay in `/root/fruits/research/EVAL-006`, digests in `RAW_MANIFEST.sha256`.

## Primary result

| arm | pass@1 (all tests + clean tamper audit) | 95% CI (Clopper-Pearson) | provider calls | input / output tokens | calls per solved | tokens per solved | wall time |
|---|---|---|---|---|---|---|---|
| SINGLE | 8/20 = 0.40 | [0.191, 0.639] | 20 | 340,242 / 4,908 | 2.5 | 43,144 | 233 s |
| ORG | 8/20 = 0.40 | [0.191, 0.639] | 253 | 3,500,852 / 89,062 | 31.6 | 448,739 | 3,049 s |

Paired: both pass 7, neither 11, SINGLE-only 1 (BigCodeBench/654), ORG-only 1 (BigCodeBench/445). Exact McNemar p = 1.00. Difference ORG − SINGLE = 0.00.
**No difference in solved tasks; the organization cost about 12.6× the provider calls, about 10.4× the tokens and about 13× the wall time for the same
8 solved tasks.** This is a negative result for the organization on this sample. With n = 20 it cannot exclude a modest effect either way (the CIs are
wide), but it gives no evidence of uplift.

Secondary (descriptive): FSE hidden-only grade SINGLE 8/20, ORG 10/20 (ORG's candidates for 1015 and 129 pass every hidden test but fail visible-third
tests, so they are not correct under the primary metric). All-tests-pass ignoring the tamper audit: 8 vs 8 (the only TAMPER rows are BigCodeBench/17 in both
arms, audit flag `kill`, which fail the tests anyway). ORG "any final position passes": 8/20, the same tasks as ORG's chosen answer.

## What the organization actually did (why the outcomes are what they are)

- **Collaboration mostly did not happen.** Brother Mode got a second solver in only 7 of 20 tasks; 13 of 20 ended `NO_SECOND_SOLVER`, so ORG's answer
  was gpt-6-luna's lone SOLUTION (`basis = consensus` over one position). In those 13 tasks ORG and SINGLE ran the same model (chatgpt-codex/gpt-6-luna)
  on the same task; ORG's prompt carried the SOLVE template, and the LSD Room had run before it. Both discordant tasks (445 ORG-only, 654 SINGLE-only) are of
  this kind. The data therefore attributes them to two different samples of the same model under different prompt wrappers, **not** to criticism, revision or
  model choice. Only 1 of 20 ORG answers is byte-identical to SINGLE's.
- **Where collaboration happened (7 tasks: 1015, 374, 574, 720, 777, 915, 916)** it never changed the outcome. Both arms fail 6 of these 7 tasks and pass
  777. 12 critiques were made (11 with DISSENT), and there were 10 revisions, each of which changed the reviser's code. The answer was always gpt-6-luna's
  (primary), and one specialist tie-break was used (916). Every final position from a second lineage failed (8 of 8: llama-3-super-nova-rp-8b, llama-3.3-70b,
  qwen2.5-vl-72b ×2, nemotron-3-ultra-550b, nemotron-3-nano-omni-reasoning, qwen3.5-9b and others). The second opinions came from much weaker free models
  than the primary. EVAL-006 did not grade gpt-6-luna's pre-revision SOLUTIONs (not pre-registered), so whether a revision broke or fixed a solution
  cannot be told from these grades.
- **The model was the same.** SINGLE used gpt-6-luna for all 20 tasks (PlumMe AUTO, competence copy). ORG's solver of record was also gpt-6-luna in all 20.
  The other 29 lineages ORG touched were LSD-Room workers, second solvers, critics and failed attempts (e.g. cerebras-gpt-111m-instruct, thea-rp-3b,
  llama-3.2-3b, jan-nano).
- **Failure classes (ORG).** Every mission ended UNRESOLVED, as pre-registered: there was no executed check, so no claim was settled. `integration_path_ok`
  was false in every mission (39 `RESEARCH_STEP_FAILED` problems, never recovered). The research-step failures were:
  - RESEARCH_BUDGET_EXHAUSTED: 11
  - EXECUTION_NOT_PERFORMED_MODEL_NOT_FOUND: 8
  - EXECUTION_NOT_PERFORMED_RATE_LIMITED: 7
  - EXECUTION_OUTPUT_UNUSABLE_SEMANTIC_OUTPUT_FAILURE: 6
  - EXECUTION_NOT_PERFORMED_CREDENTIAL_EXHAUSTED: 4
  - EXECUTION_NOT_CONFIRMED_PROVIDER_UNAVAILABLE: 4
  - NO_WORKER_SLOT: 2
  - FORBIDDEN: 1
  - EXECUTION_NOT_CONFIRMED_BUDGET_EXHAUSTED: 1

  The 90 PlumMe failure receipts were LOCAL_DENIED 57, MODEL_ERROR 16, RATE_LIMITED 8, QUOTA_EXHAUSTED 4, PROVIDER_DOWN 4 and BUDGET_EXHAUSTED 1; the
  receipts carry no failure messages. SINGLE had no failures and no retries.
- **Budget mechanism.** gpt-6-luna is served through the headless Codex route at about 16–17k input tokens per call, against a local estimate that is much
  lower. ORG averaged about 175k input tokens per task, close to the research run ceiling (worker budget 60k tokens × 3 workers = 180k). This matches the 11
  RESEARCH_BUDGET_EXHAUSTED steps: the default budgets of the 2026-11-12 operational config run out before Brother Mode can complete with this route.

## What the data does and does not show

- Shows: on these 20 BCB-Hard tasks, under the free/zero-charge supply of 2026-11-12, the full organization solved exactly as many tasks as one call of
  the same strongest model (8/20 each). It used about 10× the tokens and calls and about 13× the time. Brother Mode was usually reduced to one solver by
  supply failures and budget exhaustion. Where it worked, its extra lineages were weaker models whose positions all failed, and it did not change any
  outcome.
- Does not show: that the organization cannot help on code. Untested here: an executed host check (deliberately absent, to avoid leaking the grade),
  stronger or equal-strength second lineages, budgets sized for the headless route, and more than one round. It also does not show an effect of
  criticism or revision on correctness, because pre-revision drafts were not graded. n = 20 is exploratory: the 95% CIs [0.19, 0.64] are compatible with
  differences of several tasks in either direction.
- The 110 reserved ids were not touched; any confirmatory follow-up should pre-register the changes above before running on them.
